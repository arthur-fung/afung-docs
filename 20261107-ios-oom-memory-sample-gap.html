The memory trail stops when recording stops

2026-11-07 · iOS memory kills, SCRIBE-MOBILE-B0 · why “grew after End Visit” is not yet measured
recording_heap_sample records footprint every 30 seconds, and only while the recording timer is running. Pause and End Visit each leave one sample, then the timer is cancelled. The next number is the first sample of whatever recording starts next. Two very different stories fit those two points.

What a visit looks like in the breadcrumb trail

recording_heap_sample every 30s one sample at Pause, Resume, or End Visit dashed amber: grew during the gap dashed gray: flat, then a jump at the next sample kill with no following sample

Both dashed lines pass through the same two measured points. The net change is known. When it happened is not.

Where the timer is cut

MomentWhat the code doesWhat the trail contains
Recording ResourceMonitoringService.start samples immediately, then every 30 seconds. Breadcrumb category memory, message recording_heap_sample. A real curve. This is the 300–500 MB/min ramp.
Pause stop() cancels the timer, then one track('RECORDING_PAUSED'). A dot at pause and a dot at resume. Nothing between them.
End Visit One track(RECORDING_ENDED), then stop(). A dot at End Visit. The next dot is the next Start Recording, if the process lives that long.
Killed in the gap UIKit can still emit system.ios_low_memory. That breadcrumb is sent once per session, and the footprint value is truncated in Sentry. A timestamp for the warning. Not a memory curve.

What this leaves undecided

“Still high at the next Start Recording” is measured. The first sample of the next recording is a real footprint, often 1.9–3.2 GB. “Climbed while browsing after End Visit” is a choice between the two dashed lines. The same is true of “grew during pause”: the pause sample and the resume sample differ by about a gigabyte in one of the trails, and the minute in between was not sampled.

A kill one to eight minutes after End Visit is timed from navigation crumbs. That says when the process died. It does not say whether footprint was flat, rising, or already at the ceiling.

The addition that closes it

Where one packet goes

On iOS the mic tap hands off a small native buffer. Dart accumulates packets until the flush, then builds a WAV and an encrypted copy. The flush writes that copy into SQLite, and the upload reads one chunk back. The Dart copies live inside dart_heap_mb together. This is the path, not a measurement of the 2,743 MB.
