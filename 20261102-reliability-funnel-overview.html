The idea

Follow every recording from "tap record" to "note in the EHR", and make every number on the dashboard clickable down to the recordings behind it.

1
One row per recording

Every metric (lost, failures, incomplete, crashes…) is just a count of rows in the same table. No separately computed numbers that can disagree.

2
Exactly one outcome each

Each recording ends in one of 18 outcomes, and stores the event that decided it, so you can always see why.

3
A timeline for each

App events, uploads, backend status changes, errors and crashes for that recording, in order, each linked to its source.

To make this possible, the app and backend send a few new ids and events. We don't work around today's gaps; we close them.

App Backend Crash / OS

    Crashes

    Every crash carries the app session, device install, and the recording when there is one. The existing Crashlytics + Sentry → BigQuery pipeline stays; we add one row per crash and copy it to StarRocks.

    During a recording

    Shows on the recording's timeline. If the recording never reached the backend, its outcome is Killed: crash.

    During upload / recovery

    Linked through the device's list of open recordings, so a crash while retrying an old upload still points at that recording.

    Outside a recording

    Login, settings, startup. Linked to the app session, and counted in our own crash-free sessions rate.

    The crash list ranks issues by recordings lost, then sessions affected. Every count opens the list behind it.

    Switch to the new events, add crashes and alerts

    • Classify recordings from the new events

    • Backend stage events, Grafana alerts
    • Data-quality strip
    P2 · Depth

    Finer splits and cut-over

    • OS exit reasons: crash vs low memory vs user closed
    • Note viewed / copied, recording id in backend logs
    • Move the OKR to the new numbers at ≥95% coverage

    During rollout, old app versions are classified from today's events and new ones from the new events. Both are shown separately and combined, so upgrades don't look like reliability changes. Old and new scorecards run side by side for 4 weeks before switching.
