Missing in the v2 API

  1. No list of all site providers with provider_id (row 14b). Writes take provider_id, but site_user_template_assignments lists scribe accounts without it, and /providers, /template_coverage and /missing return only subsets. Planned in PR 10 (#60362): GET /appointment_rules/providers with appointment_type optional. Without it, the endpoint returns every active site provider (the set writes accept), with has_template for template_id, is_explicit: false, and the usual search, facility_id and paging. Spec: 20261025-template-appointment-linking-fe-api-spec.md, GET /appointment_rules/providers section.

Decisions

  1. v0 is acceptable. Using v0 doesn't fail a row on its own; the Check column scores behaviour only.
  2. v2 swap is the plan. Replace the v0 view model with the v2 client (AppointmentRulesV2Repository, already on develop from #6358), and use missing_rules / GET /missing instead of the client-side counts. That fixes rows 1–4, 9 and 16. Anything the screens need that v2 can't provide is listed under "Missing in the v2 API".
  3. Move is a simple move. It moves one or more providers to another existing rule of the same type, with one PATCH /{target}/providers. No template change.

Changes needed in Move

  1. Step 1 lists the type's other rules (from GET /appointment_rules), not every site template.
  2. Remove step 2 ("Which template should they use instead?").
  3. Ask what happens to moved providers who don't have the target's template (providers_without_template: ADD_TEMPLATE / PERSONAL_RULES), as Delete does.
  4. Confirm before moving a rule's last provider, since that rule is then deleted.
