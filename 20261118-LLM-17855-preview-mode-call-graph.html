Preview mode: how the backend should generate the note

LLM-17855 · Customize 2.0 · Updated 2026-11-18

Summary
  • Preview should produce the same note a real scribe would, using the template's current config.
  • Recommendation: Option B. A new normandy endpoint builds the normal note-generation payload and calls errands' existing note generation directly. Errands returns the note in the response and skips the normal callback, so nothing is saved and no follow-on work runs.
  • Errands already supports this: is_note_metrics_engine_env returns the note instead of calling back. Errands' note-quality test tool uses it today.
  • Effort: about ½ week to 1 week, about the same as calling the LLM directly, but the output comes from the same code as a real note.

4. Open checks before building Option B

Errands' other calls back to normandy during generation

Before the final callback, errands sends status and tracking events (send_scribe_status_message_to_normandy, send_scribe_track_event). With no real scribe or task, confirm these don't fail the request.

Payload builder variant in normandy

trigger_single_workflow_task (app/api/v1/scribe/workflows/services.py) expects a workflow task, workflow and scribe. Preview needs a variant built from a template, an account and a transcript, without changing the path real notes take. This is the main normandy work.

Synchronous HTTP call from normandy to errands

Real notes go through Cloud Tasks. Preview needs a direct, blocking call with errands' auth. Check whether normandy already has a client for that.

Timeout and wait time

Generation can take 30–90 s for a long transcript. Confirm the gateway timeout allows it, or switch to start-then-poll (about +1 day).

Access, rate limit, patient data in logs
  • "Latest scribe" must be the provider's own. Admin panel use needs the same scribe_account_id site-admin check as LLM-21928 / LLM-21929.
  • Each preview is a full generation, so add a per-user rate limit (@dynamic_rate_limiter).
  • Don't log the full prompt. The old preview endpoint logs it at info level, transcript included.
Long transcripts

The real path compresses very long transcripts. Reuse that, or cap the preview's transcript length.
