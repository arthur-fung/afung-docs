LLM-20423: Incomplete Scribe with insufficient transcript information

Investigation report · 2026-10-15 · Scribe 22715665 (account 308098, iOS 3.40.1+3) · All times UTC

Summary. The iPhone recorded 173.9 s of digital silence from a USB audio input (Jieli Technology USB Composite Device). The app was in the background for almost the whole recording, so the "Audio is low" toast could not appear, and the visit was ended 1.8 s after the user returned. The backend received the full file intact and correctly reported "no speech detected". The failure is on the capture side; the pipeline behaved correctly. The same silent-start signature appeared on the same device in one other recording, where the user paused and resumed and recovered.

This rules out truncation, a dropped upload, a preprocessing problem, and a faulty amplitude meter. The input delivered zeros from the first sample to the last.

3. Why the user was never warned

  • Mute detector never fired. A frame counts as muted only at or below -150 dB (recorder_configs.dart, recorder.dart:291). The signal read -120 dB, so no muted frame was counted and no MUTED_RECORDING event exists.
  • Low-audio detector did fire, but the toast was suppressed. recording_screen.dart:1074-1133 shows the toast only when the app lifecycle is resumed; the event is logged either way. The app was paused from 18:18:36 to 18:21:26.
  • No time to notice in the foreground. The first 2.4 s was too short for the low-volume timer, and the last 1.8 s after returning was too short for a toast.
  • No check at stop or upload. Audio validation only checks that the file exists with a size above zero (upload_error_handler_service.dart:154-165, result SOME_PARTS_VALID).
  • Not memory. lowMemory: false throughout; no memory-related errors near the recording.

4. Input source

Not in scribe_events or Sentry. It was found in the app's own logs in GCP project athelas-scribe-mobile (filter by labels.recording_uuid): AppleUSBAudioEngine:Jieli Technology:USB Composite Device. Jieli is a chip maker, so this is probably an off-brand USB audio device or adapter; the product is unknown. No route change, device change, interruption, disconnect, or "Mic muted" log appears during the recording.

  • Sentry. Nothing relates to this recording. The 13 errors for the user in the last 7 days, and the 31 groups over 90 days, are all hours to months away from 10-13 18:18–18:22.
  • Account history. Of the 100 most recent scribes for account 308098 since 09-15, this is the only INCOMPLETE one; the rest are SYNCED or PRE_CHARTED (no audio).

8. Open questions

  • Why the device goes silent. A hardware mute on the device and a USB audio-session fault are both possible. There is no evidence for either.
  • The clinician's actual setup and whether they were speaking. Needs Danielle, Shailee or the user.
  • The 2 s shown in the UI against 173 s in the data. The client's own cache recorded 173.875 s ("3 min"). The 1.8 s after returning to the foreground matches the figure, but that is a correlation, not a confirmed explanation.
  • How the failing starts differ from the working ones (time since the previous recording, USB reconnects, pause and resume patterns). Not yet compared.
  • Whether this is specific to this user. Not checked across other users on the same device.
